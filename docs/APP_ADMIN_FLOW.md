# ربط شاشات التطبيق بالـ API ولوحة التحكم (Admin Panel)

هذا الملف يوثق أن كل الشاشات والمميزات في التطبيق مرتبطة بالـ Backend API وبلوحة التحكم، وأن الـ Flow يعمل بشكل طبيعي.

---

## 1. المصادقة والمستخدم

| الشاشة | الـ API | لوحة التحكم |
|--------|---------|-------------|
| **تسجيل الدخول** (login_screen) | `POST /api/login` | — |
| **التسجيل** (signup_screen) | `POST /api/register` → ينشئ User + UserVerification (pending) | **المستخدمون** + **توثيق المستخدمين** |
| **تسجيل الخروج** | `POST /api/logout` | — |
| **الملف الشخصي** (me) | `GET /api/user`، `PUT /api/user` | **المستخدمون** (تعديل)، **توثيق المستخدمين** (حالة الوثائق + تم التحقق من الهاتف) |

- بيانات الصفحة الشخصية (التحقق من الوثائق، التحقق من الهاتف، التقييم، أرقام الهاتف) كلها من الداتا ومربوطة بتوثيق المستخدمين في الأدمن.

---

## 2. البحث والشحنات والرحلات

| الشاشة | الـ API | لوحة التحكم |
|--------|---------|-------------|
| **البحث** (search_screen) | `GET /api/places`, `GET /api/shipments`, `GET /api/trips`, countries/cities | **الشحنات**، **الرحلات**، **الدول**، **المدن** |
| **تفاصيل الشحنة** (shipment_details_screen) | `GET /api/shipments/{id}` | **الشحنات** (عرض/تعديل) |
| **شحناتي** (my_shipments_screen) | `GET /api/shipments` (مع user) | **الشحنات** |
| **إضافة شحنة** (add_shipment_screen, add_shopping_shipment_screen) | `POST /api/shipments` | **الشحنات** |
| **حذف شحنة** | `DELETE /api/shipments/{id}` | **الشحنات** |
| **رحلاتي** (trips_screen) | `GET /api/trips`, `POST /api/trips`, `DELETE /api/trips/{id}` | **الرحلات** |
| **إضافة رحلة** (add_trip_form_screen) | `POST /api/trips` | **الرحلات** |
| **تفاصيل الرحلة** (trip_details_screen) | `GET /api/trips/{id}` | **الرحلات** |

---

## 3. الطلبات (تطابقات) والاتفاقات والدفع والتقييم

| الشاشة / الميزة | الـ API | لوحة التحكم |
|------------------|---------|-------------|
| **قائمة الطلبات** (تبويب تطابقات - messages_screen) | `GET /api/requests` | **الطلبات (Requests)** |
| **قبول طلب** | `PATCH /api/requests/{id}/accept` | **الطلبات** |
| **رفض طلب** | `PATCH /api/requests/{id}/reject` | **الطلبات** |
| **دفع طلب** (shipment_payment_screen) | `POST /api/requests/{id}/pay` → ينشئ Payment + Conversation | **الطلبات**، **المدفوعات (Payments)** |
| **تقييم الطرف الآخر** | `POST /api/requests/{id}/rate` | **التقييمات (Ratings)**، وتحديث **المستخدمون** (rating) |

- التقييم يحدّث تلقائياً متوسط تقييم المستخدم (RatingObserver) ويظهر في الصفحة الشخصية وفي لوحة التحكم.

## 6. الدعم الفني والمزيد

| الشاشة | الـ API | لوحة التحكم |
|--------|---------|-------------|
| **الدعم الفني** (technical_support_screen) | `POST /api/support-tickets` (بعد تسجيل الدخول) | **تذاكر الدعم (Support Tickets)** |

## 7. ملخص الـ Flow

1. **التسجيل والتوثيق**: تسجيل → User + UserVerification (pending) → يظهر في **توثيق المستخدمين** → الموافقة/الرفض تحدّث حالة المستخدم وتم التحقق من الهاتف في الأدمن وتظهر في **الصفحة الشخصية**.
2. **الشحنات والرحلات**: إضافة/عرض/حذف من التطبيق ↔ نفس البيانات في **الشحنات** و**الرحلات** في الأدمن.
3. **الطلبات والدفع**: طلبات من التطبيق → قبول/رفض/دفع من التطبيق → المدفوعات تظهر في **المدفوعات**، المحادثات في **المحادثات** و**الرسائل**.
4. **التقييم**: تقييم من التطبيق بعد الاتفاق → يظهر في **التقييمات** ويحدّث **تقييم المستخدم** في الأدمن وفي الصفحة الشخصية.
5. **المحتوى**: بنرات، أسئلة شائعة، إعدادات، دول، مدن، عملات، طرق دفع ← كلها من الأدمن وتُعرض في التطبيق.
6. **الدعم الفني**: إرسال تذكرة من التطبيق → تظهر في **تذاكر الدعم** في الأدمن.

---

## 8. إصلاحات تمت في هذا التحقق

- **الدعم الفني**: إضافة `POST /api/support-tickets` وربط شاشة الدعم الفني بالـ API حتى تظهر التذاكر في لوحة التحكم (Support Tickets).

بهذا تكون كل الشاشات والمميزات المذكورة أعلاه مربوطة بالـ API وبلوحة التحكم، والـ Flow يعمل من التطبيق إلى الأدمن وبالعكس حيث يقتضي الأمر.
